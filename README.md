# Hermes Pocket

A native Android companion for Hermes Agent on a home server. The design combines a session-focused workspace, dark charcoal/gold conversation UI, and an inspectable activity screen.

This is an early implementation, not an official Nous Research Android release. It is a separate product repository; Music and the other Agent project are unchanged.

## Product layout

- `apps/android/` — Kotlin, Jetpack Compose, Material 3 app.
- `docs/` — development and gateway compatibility notes.
- `scripts/verify-android.py` — unit tests, Android lint/build, optional emulator-only UI tests.

Open `apps/android` in Android Studio. See [development notes](docs/development.md) for SDK requirements and command-line verification.

## First-run behavior

The app starts offline without making a server request. Connect explicitly or choose **Explore demo** to try sample conversations and approval UI. Demo content and responses are labeled; they are not generated by your server. Demo commands never run.

The real connection path targets Hermes's canonical remote gateway API, not a new custom backend. It uses authenticated JSON-RPC over WebSocket and negotiates capabilities before loading sessions.

## Connecting

You need a remote Hermes deployment that actually exposes the Desktop HTTP/WebSocket gateway, a valid HTTPS origin with a trusted certificate, and a gateway session token already provisioned by that deployment.

- Enter the HTTPS origin and session token in the Android connection screen. **Do not paste credentials into a chat or commit them to this repository.**
- The credential is a **gateway session token**, not an inference/model API key or a Nous model-provider OAuth token.
- A successful public HTTP status response alone does not count as an authenticated connection. Runtime negotiation and session listing must succeed.
- Access to a gateway can grant agent execution access on its host. This app does not create a fictional read-only mobile security scope.
- Credentials stay in process memory. The last gateway origin is the only locally persisted connection setting. Sign in again after process death. Android backup is disabled.

## Initial scope and limitations

- One gateway and its configured default profile; HTTPS root origins only (no reverse-proxy subpath in this version).
- Canonical session-authority API required. Legacy sidecar payloads are not silently mixed with canonical requests.
- Recent stored sessions, create/resume, text chat, and streamed tool activity.
- Session listing is bounded; the UI must not claim to show the entire server history.
- No automatic retry of an unconfirmed message and no automatic reconnect/replay yet. Review or resume the session after a connection failure; the server may still be working.
- Approval UI is local demo functionality only. Real approvals and clarifications must be handled on the desktop in this first version.
- No native browser OAuth/PKCE, multiple connections, voice, attachments, arbitrary artifact downloads, background notifications, or release signing/update delivery yet.
- Debug APK builds are for development. On each push to `main`, GitHub Actions runs unit tests and lint, builds a debug APK, and publishes it as a **prerelease**; it is not production-signed. The release tag and APK version name are `v0.1.N` / `0.1.N`, where `N` is the full Git commit count, and the Android version code is `N`. See [development notes](docs/development.md) for release details. A home-server URL and authentication method have not been supplied, so a real home-server end-to-end test is still required.

Nothing in this repository automatically changes a home server, provisions a credential, weakens TLS, or exposes a local service to the internet.
